# 배포 포털 사용법

이 포털은 초대받은 사용자가 GitHub 저장소를 선택해 공개 HTTPS 서비스로 배포하는 도구입니다. 포털 로그인과 GitHub 연결은 서로 별개입니다.

## 1. 포털 로그인

1. [배포 포털](/login)에 접속합니다.
2. 관리자가 전달한 이메일과 임시 비밀번호로 로그인합니다.
3. 첫 로그인이라면 새 비밀번호를 설정합니다.

비밀번호를 잊었거나 임시 비밀번호가 만료된 경우 관리자에게 재발급을 요청하세요. 이메일 발송이나 자가 비밀번호 재설정은 제공하지 않습니다.

## 2. GitHub 연결

처음 배포할 때만 **GitHub 연결**을 선택합니다. GitHub는 저장소와 브랜치 목록을 불러오는 데만 사용하며, 포털 로그인 수단은 아닙니다.

연결을 해제하면 저장소 조회와 새 배포가 중단됩니다. 기존에 배포된 서비스는 계속 열립니다.

## 3. 저장소 배포

대시보드에서 다음 세 단계만 진행합니다.

1. **저장소 선택**: 검색창에 저장소 이름을 입력하고 목록에서 선택합니다.
2. **버전 선택**: 기본 브랜치가 먼저 선택됩니다. 필요할 때만 다른 브랜치나 태그를 고릅니다.
3. **배포 시작**: 포트, 빌드 방식, 서비스 이름은 저장소를 분석해 자동으로 결정됩니다.

Dockerfile, Node 웹앱, 정적 HTML 사이트를 자동으로 감지합니다. 자동 판단이 어려운 저장소는 배포 전에 필요한 수정 사항을 안내합니다.

## 4. 배포 결과 확인

배포 상세 화면에서 상태가 자동으로 갱신됩니다.

- **준비 중 / 진행 중**: 배포가 진행되고 있습니다.
- **배포 완료**: **서비스 열기**를 눌러 공개 주소로 이동합니다.
- **배포 실패**: 화면의 안내를 확인하고 저장소의 필요한 파일을 수정한 뒤 다시 시도합니다.

서비스 주소는 링크를 아는 사람은 열 수 있지만 검색엔진에는 노출되지 않습니다. 기술 정보는 **배포 정보**를 펼쳐서 확인할 수 있습니다.

## 5. 관리자 기능

관리자는 **팀원 관리**에서 이메일 계정을 만들고 역할을 지정할 수 있습니다.

- 새 계정 생성 및 임시 비밀번호 발급
- 임시 비밀번호 재발급
- 사용자 활성화·비활성화
- 관리자·일반 사용자 역할 변경
- 활동 기록과 배포 이력 확인

임시 비밀번호는 발급 화면에서만 확인할 수 있으므로 사용자에게 안전하게 전달하세요.

## 문제 해결

1. 로그인할 수 없으면 이메일·비밀번호를 확인하고 관리자에게 임시 비밀번호 재발급을 요청합니다.
2. 저장소가 보이지 않으면 GitHub 연결 상태를 확인하고 다시 연결합니다.
3. 배포가 오래 진행되면 상세 화면을 새로고침합니다.
4. 서비스 링크가 열리지 않으면 관리자에게 배포 이름과 화면에 표시된 오류를 전달합니다.
