# 배포 포털 사용법

이 문서는 승인된 GitHub 저장소를 배포하는 비공개 배포 포털의 기본 사용법을 설명합니다.

## 1. 로그인

1. 포털에 접속합니다.
2. **GitHub로 로그인**을 선택합니다.
3. 관리자가 허용한 GitHub 계정으로 인증합니다.

허용되지 않은 계정은 로그인할 수 없습니다. 계정 추가가 필요하면 관리자에게 GitHub 로그인 아이디를 전달하세요.

## 2. 저장소 배포

대시보드가 GitHub 권한으로 배포 가능한 저장소를 자동으로 불러옵니다. **저장소 검색**에 이름이나 설명을 입력하고 목록에서 저장소를 선택하세요. 저장소를 선택하면 기본 브랜치와 애플리케이션 이름이 자동으로 채워지고, 브랜치 목록도 선택할 수 있습니다.

| 항목 | 입력 방법 |
| --- | --- |
| 저장소 검색 | 저장소 이름이나 설명으로 검색한 뒤 목록에서 선택 |
| 브랜치 | 저장소 선택 후 GitHub 브랜치 목록에서 선택 |
| 애플리케이션 이름 | 저장소 이름을 바탕으로 자동 생성. 필요하면 수정 |
| 포트 | 애플리케이션이 사용하는 포트. 기본값은 `3000` |
| 빌드 방식 | 특별한 이유가 없으면 `자동`을 선택 |

GitHub 저장소 목록을 불러오지 못하는 경우에만 **저장소를 직접 입력**을 선택해 수동으로 진행할 수 있습니다.

자동 목록은 관리자가 설정한 허용 소유자만 표시합니다. 비공개 저장소를 표시하려면 GitHub 로그인 때 저장소 읽기 권한을 승인해야 합니다.

입력을 마치면 **저장소 배포**를 선택합니다. 저장소 소유자가 배포 허용 목록에 없으면 배포가 거부됩니다.

## 3. 배포 결과 확인

배포 상세 화면에서 상태가 자동으로 갱신됩니다.

- **요청됨 / 준비 중 / 대기 중 / 진행 중**: 배포가 진행 중입니다.
- **정상**: **애플리케이션 열기**로 서비스에 접속할 수 있습니다.
- **실패**: 저장소의 빌드 설정과 브랜치를 확인하고 다시 시도합니다.
- **확인 불가**: 잠시 기다린 뒤 **상태 새로고침**을 선택합니다.

## 4. 애플리케이션 인증정보 확인

배포 상세 화면에서 **인증정보 보기**를 선택하면 기본 인증 사용자 이름과 비밀번호를 확인할 수 있습니다. 비밀번호는 필요한 순간에만 표시하고, 메신저나 문서에 남기지 마세요.

## 5. 관리자 기능

관리자에게는 다음 메뉴가 표시됩니다.

- **사용자 관리**: 허용된 GitHub 계정 추가, 역할 변경, 사용자 활성화·비활성화
- **감사 로그**: 로그인, 배포 요청, 인증정보 표시, 권한 변경 기록 조회

관리자를 비활성화할 때는 활성 관리자가 한 명 이상 남아 있어야 합니다.

## 문제 해결

1. 로그인할 수 없으면 GitHub 계정이 허용 목록에 있는지 관리자에게 확인합니다.
2. 배포가 계속 진행 중이면 상세 화면에서 **상태 새로고침**을 선택합니다.
3. 배포가 실패하면 저장소의 빌드 방식, 브랜치, 포트를 확인합니다.
4. 서비스 자체에 접속할 수 없으면 잠시 후 다시 시도하고 관리자에게 배포 이름을 전달합니다.
